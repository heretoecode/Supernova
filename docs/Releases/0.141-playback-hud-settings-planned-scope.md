## Approved HUD and Settings visual contract (22 October 2026)
- Normal playback: minimal, cinematic, unobstructed video; **play/pause control on the far left**; slim blue seek/progress bar; conditional chapter markers where accurate chapters are available; seek-position tooltip; remaining-time and estimated finish-time on the right; **no duplicate elapsed timestamp under the left end of the bar**.
- Settings: right-aligned dark translucent popup, leaving most of the video visible; **four horizontal tabs across the top in this exact order: Subtitles | Audio | Display | Playback**. Never substitute a vertical left sidebar or rename Display to Video.
- Subtitles is the first tab and the selected tab in the approved open-Settings mock-up. Blue focused/selected state consistent with Supernova's existing focus treatment; clearly visible individual option focus for D-pad use.
- Settings button can be hidden when the popup is open to avoid duplication; confirm actual navigation/focus behaviour during implementation. No Technical Information or Report a Problem entries in the playback UI.
- Mock-up labels, values, and example content are **illustrative**; the audited, genuinely supported controls and conditional availability govern the actual menu. Do not introduce fictional settings such as unsupported downmix/spatial audio/night mode merely because generated artwork shows them.
- Preserve subtitle workflows, Back/dismiss, persistence, accessibility, playback/seek behaviour, and underlying diagnostics. Tweak the appearance only after owner Shield QA, without reopening the approved overall layout.

## Functional grouping
- **Audio:** track selection, audio delay and associated global persistence, boost, night mode, spatialization when supported.
- **Subtitles:** tracks/none/other languages, delay and speed adjustment, appearance (size, colour, position, outline, background, opacity), download/local file workflows, reading/download languages and subtitle preparation/default preferences. Minimise unnecessary exits to full app Settings.
- **Display:** existing format/aspect options, conditional 3D and Picture in Picture. **Audit note:** Format already contains aspect options; do not create an independent duplicate Aspect Ratio control merely because an illustrative mock-up shows one.
- **Playback:** playback speed and global persistence, play modes, segment skipping.
- Keep transport/seeking, contextual Skip and Up Next outside the settings popup; preserve conditional capability checks, destructive confirmations, and D-pad accessibility.
- Owner-approved removal **from playback UI**: Technical Information and Report a Problem. Retain underlying diagnostic logging and support infrastructure unless separately approved for removal.

## Quality and decisions
- Investigate, prioritise and correct the 14 source-backed findings from the audit, confirming runtime behaviour and applying relevant fixes. Do not conflate all limitations with defects.
- Review all audit option IDs against final design so nothing else disappears inadvertently. Make persistence, focus, timing, back/dismiss, hardware conditions and unavailable states explicit.
- Overall HUD and four-tab Settings layout are **owner-approved**. Codex must resolve detailed focus/scroll/interaction behaviour, including dense Subtitles content, against the existing functionality audit without requiring routine engineering decisions from the owner; ask only for genuine design-preference conflicts.
- Online chapter sources are a **proposal for separate feasibility and accuracy review**, not an approved dependency or guaranteed feature for 0.141. Embedded chapter display is conditional on available, reliable metadata.
- No source changes, APK builds, merges or changes to 0.140 are authorised by this scheduling document.

## Global language labels and flags — owner request (22 October 2026)

**Scope:** App-wide design requirement for the next Supernova development session / planned 0.141 work. Wherever the UI displays a language (audio/subtitle tracks, language settings, metadata, search/filter choices, download language choices, etc.), show an appropriate flag or language-identifying icon next to the readable language name, consistently across screens.

**Mapping rule:** Do not infer a country from a language alone: language-only codes (e.g. en, es, pt) are not equivalent to UK/US/Spain/Portugal. When reliable region metadata exists (e.g. en-GB, pt-BR), show the corresponding country flag. Otherwise show a neutral language/globe icon rather than an arbitrary national flag. Avoid flags for unknown/undetermined, commentary and other non-language labels. Preserve locale names, accessibility descriptions, text truncation, layout and D-pad focus. Audit existing language renderers and centralise mapping so behaviour is global, including newly added screens. Verify on Shield with language-only, region-tagged, unknown and mixed-language examples. No code changes authorised by this documentation update.
