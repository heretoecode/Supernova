## Coverage and evidence

All **12 approved categories** were traced through XML inflation, `VideoPreferencesCommon`, `PreviewSettings.organise/consolidate/sidebar`, inline choices and special workspaces. Inventory rows count preference/action definitions, including hidden/conditional ones, not the number simultaneously visible on a Shield. Dynamic country/provider rows and repeated Home rows are templates. NAVIGATION defines screen/state templates and auxiliary controls separately; do not add these overlapping counts into a purported number of user settings.

“Source wired” means a declaration and handler/consumer path exists. It does not establish service success, hardware effect, persistence under disk failure, or physical focus correctness. “Hidden” is not “dead”: compatibility, classic-interface and migrated proxy state can still affect playback. Consumer references in the inventory are trace leads, not proof that every use is active in this build. Declared XML summaries are recorded verbatim; runtime descriptions and overrides below take precedence for actual organised Settings.

Two confirmed source defects are recorded, both P2 (F01 and F02). No P0/P1 defect is established. Higher-risk hypotheses (numeric input and legacy advanced reparenting) remain explicitly unverified. No crash, credential leak, lost user setting or device regression is claimed without evidence.

## Category contracts and actual behaviour

### Playback

`playback_speed` enables speed controls rather than setting the speed itself. Actual speed/Keep are player controls. Passthrough and decoder selection constrain availability; `audio_speed_audiotrack` lives under Audio Compatibility. Other-player launch (`allow_3rd_party_player`) delegates to Android and may lose Supernova resume/bookmark features, as its description warns. `network_bookmarks` controls read/write attempts on writable network media; a read-only server cannot be made writable by this toggle. `hide_controls_on_pause` changes HUD timeout. Projector mode aligns video at top and remains a real control; the organiser's legacy list does not retire it. Display-resume-box and remembered brightness are phone/classic dependent and removed for Leanback in the common controller. Preferences persist immediately; playback-engine setup may read them only on the next playback/reinitialisation. A Settings checkbox is not proof of live engine reconfiguration. Test an already-playing video separately from a new launch.

### Video

Refresh switching is a mode list, default 0, constrained by device display support; 3D switching is TV-only. Dolby Vision is default `auto`; mode lists are capability-adjusted and the common controller saves a valid fallback. Preserve conversion/suppression choices and Android display restoration on playback exit. Decoder/parser/i-frame controls live under Advanced, with an additional inherited advanced-unlock gate. Cutout controls are removed on Shield. Refresh-rate transitions, HDR/Dolby Vision colour/blackouts and actual decoder selection need physical Shield/AV-chain evidence.

### Audio

Passthrough mode defaults Off (0), with modes from the source array. The legacy force flag is independent and only useful when passthrough is active. Unsupported devices disable passthrough; setup migrates older force state and resets speed when passthrough requires it. Decoder choice is default 1; speed/AudioTrack/dynamic delay controls depend on passthrough, decoder and frame-timing capability. Spatialization defaults Off, requires compatible Android/output, and overrides downmix choices; the player audio menu shares its saved preference. TV force-downmix and handheld disable-downmix are opposite, device-specific controls deliberately retained as separate keys. Original-track preference and preferred language affect track selection, with fallback when no matching track exists. Do not deduplicate these by deleting keys. HDMI receiver changes, multichannel voice, sync, Bluetooth and speed effects require real output tests.

### Subtitles

The visible positive `preview_subtitles_by_default` proxy persists the inverse in `subtitles_hide_default`; matching forced-track policy remains separate. Default positive value is On. The proxy calls `original.setChecked()` without invoking the common listener that enables/disables `favSubLang` (F02). Changing the proxy updates storage but can leave language availability stale until reconstruction. Reading and download languages use OpenSubtitles' runtime list, with system-language fallback. Empty download-language selection is replenished from the locale when the screen is rebuilt; do not assume an empty set is durable intent. Encoding default 0 delegates to native codepage; the first label reflects the native default. Preparation is default Off, season preparation On, and is gated by OpenSubtitles integration and Private Mode. It caches searches, never downloads automatically or searches during import. It uses local episodes and paced season work. Credentials are under Integrations, encoding under Advanced. Player subtitle track/file/style/delay operations are separate playback surfaces; preserve their existing per-title and global ownership.

### Library & Metadata

Remember views defaults On and owns separate Movies/TV presentation state; it does not own Home or source membership. Hidden/watched filters, sort-article rules, remote thumbnails and Display all files retain existing consumers. Display all files shares state with the Network & Files toolbar and must not accidentally widen indexing. Automatic metadata lookup defaults On and explicitly stores the value before starting AutoScrapeService. Description language affects subsequent scraping; existing metadata needs an explicit rescrape. NFO parsing/auto-export and duplicate-information reuse are independent policies, with writable-source restrictions. Rescrape all/movies/collections use confirmation and service flags; recreate-sort-titles recomputes database fields; manual NFO export is a real export operation. Raw media-db export and adult scraping are inherited advanced/build gated. Full Library Scan, scan-on-return and interval preferences are constructed then hidden: scheduling now belongs Network & Files, intentionally avoiding duplicated controls. Their storage/backend must remain compatible.

Track Watch History and Remember Playback Position both default On and are independent. Turning off tracking retains prior history; Clear Viewing History confirms deletion and preserves unfinished positions, media and sources. Backup inclusion is separate from tracking. Library database services and view caches may update asynchronously; persistence of a switch does not imply a completed rescrape or immediately refreshed list.

### Home

Three Featured toggles default On, selecting Recently Added / Trakt Trending / Trakt Popular from matching local-library titles with offline fallback. They do not stream unrelated online titles. Home rows opens the production CustomiseHomeEditor. Seven built-ins are restored if missing and retain canonical names; reorder and hide are allowed while their contents are managed. Custom rows own name (40 chars), icon, Movies/TV/Both, genre selection and Match Any/All, Date Added/Title/Year, ascending/descending, maximum 5/10/15/20/25/30, and automatic inclusion. New custom maximum is 15; old unlimited values normalise to 30. Turning automatic inclusion off freezes calculated membership into explicit members. JSON `preview_home_rows41` persists changes; move mode commits with OK and cancels with Back. Unnamed draft discard and row deletion are confirmed. Clear Watch Next removes queue membership only. Old row/sort controls remain hidden/disabled for classic compatibility; they are not replacements for this editor.

### Appearance

UI language is a runtime list plus System; acceptance saves `ui_lang`, updates locale and restarts the activity. XML title/cache limitations are acknowledged in the common source. Accent & Colour offers Slate Blue/Cyan/Emerald/Purple/Amber/Red/Custom; default `preview_accent41=0xff62bbf3`. Custom RGB channels are 0–255 and Apply persists an int then recreates Settings. Hardware Left/Right adjusts sliders. `app_theme` is hidden legacy state for classic surfaces. `ui_zoom` is device dependent and removed on Leanback. Generic-language icons use a globe; real regional locales can use bundled flags; Cantonese `zh-ca` maps to `yue`, avoiding an invented Canadian identity.

### Streaming

This is availability and provider launching, separate from Put.io cloud file access. `LINKS_AVAILABLE=true`, enable default Off, country default IE. Country values are ISO countries sorted by localised name. Search is trimmed/case-insensitive and transient; Show all is transient Off. Popular view uses the initial 15 catalogue entries plus selected providers. Provider selections and preferred-provider IDs persist per country. Missing selected provider IDs get “Saved provider” fallback rows; preferred selection resets to Automatic if no longer selected. Catalogue cache is per region. Refresh invalidates/reloads; generation and fragment guards suppress stale UI results. Empty/loading/failure are status summaries; the focused adapter rebind can refresh help, so stale status is a device hypothesis, not a confirmed defect (F04). My Providers inline path rebuilds and regroups after every toggle and moves focus to a neighbour (F01); the older modal path updates checks in place and includes Done. Colour logos are bound without artwork tint. PreviewProviderIcons resolves catalogue logo paths back to known bundled provider marks; it does not fetch arbitrary catalogue artwork. Unknown/missing marks use a generic streaming glyph (D04). Slow loads, country switching and image failures need device QA.

### Network

Current direct controls are VPN preference/mobile-over-VPN eligibility and SFTP server identities. Identity list empty state explains first-use trust; recorded-host reset has Cancel and per-host confirmation and must only follow independent key verification. Trust reset does not test connectivity. SMB/SSH backend/discovery and buffer controls are under Advanced; credentials, sources and normal scheduling belong Network & Files. `share_folders` is hidden after organisation; existing credential-management backend must remain accessible through its owning network workflows. No new storage-service sign-ins are implied. Changing a transport preference can require reopening a connection/discovery; it is not retroactive proof that an existing session was rebuilt. Sources, exclusions, permissions and passwords are not ordinary Settings backups.

### Integrations

Landing switches for Trakt/OpenSubtitles/IntroDB default On; credentials and policies are retained when disabled. Hidden model switches are mirrored by landing SwitchCompat controls. Enabled child sections are built when expanded. A child absent because disabled is not created merely by reenabling; reopen expansion (V04). Trakt sign-in uses its real custom preference/dialog; authenticated state gates scrobbling, resume sync, force push/pull and sign-out. Resume sync additionally depends on scrobbling. Retired collection-sync is disabled/hidden for Trakt v2. Force operations are explicit one-shot account actions, not local-only toggles. Signed-out failures and service recovery require a real account.

OpenSubtitles uses an inline Username, Password, Show Password, Save & Sign In form. Username rejects empty, max 128; save rejects missing fields; authentication runs asynchronously. Credentials persist privately in `opensubtitles_credentials` only after successful login; failure keeps previous credentials. Generation/visibility checks suppress late UI updates. Private storage is not a claim of keystore encryption. IntroDB policies cover INTRO/RECAP/OUTRO/CREDITS/PREVIEW. Modes are NORMAL/PROMPT/AUTO/SMART; INTRO default PROMPT, RECAP/PREVIEW SMART, OUTRO/CREDITS AUTO. Smart recap auto-skips only on binge arrival. Missing, uncertain or unsafe bounds play normally; safe skip rejects invalid/end-of-file targets. These defaults were checked against SegmentSkippingPolicy and the pinned IntroSegments enum.

### Advanced

Six children are present: Video Compatibility, Audio Compatibility, Network Compatibility, Subtitle Compatibility, Backup & Restore, Diagnostics. Highlighting Advanced now shows a caution introduction rather than diagnostic preferences. OK/Right expands children while leaving focus on Advanced; Down chooses the first child. Diagnostics is explicitly selectable and all six existing actions are moved into it. The October 9 bypass mechanism is **addressed in source**, not newly reproduced or physically accepted. Existing SettingsShieldNavigationTest exercises reverse entry from About and diagnostic reachability. Export uses DiagnosticExportActivity and Android Files, with private local ZIP generation and error handling; returning focus remains a Shield acceptance item.

Diagnostic Logging defaults enabled, level defaults `qa` (Detailed QA), with `normal` alternate. Disable dialog: Cancel / Keep saved logs / Delete saved logs. Issues Digest is asynchronous; Report a Problem chooses Playback/UI/Network/Other and creates a local reference; no upload is implied. Logging Off explains why reporting cannot record a marker. Show Latest Reference has a no-reference state and readable/QR fallback. Diagnostic level changes are observed by Diagnostics; exporting reports is separate from changing level.

Compatibility controls retain inherited capability and advanced-unlock gates. A fresh settings model can omit decoder/interface/parser/buffer and some discovery controls even though the child exists. Rapid repeated Force software decoding clicks still trigger the inherited advanced-mode mutation path after organiser reparenting (V02). No claim that every Advanced child exposes every inventory row on Shield.

Backup & Restore is the logical backup workspace, not the obsolete whole-library description from the XML. Export Backup, Restore Backup, 26 independent category toggles, See full details and Restore instructions are live. Defaults and ownership are in S140–S165. History/position choices mirror legacy inclusion flags. Export choices synchronously commit and report save failure; restore review choices remain temporary until confirmation. Locations Off requires privacy consent; history exclusion warns about restored watched state. Export stages and verifies private data before ACTION_CREATE_DOCUMENT; retry retains verified staging. Restore uses ACTION_OPEN_DOCUMENT, archive inspection, review, selected-replacement preview and explicit confirmation. Selected empty categories clear owned state; unselected/missing categories remain unchanged. Accounts, authentication, access grants, artwork/media and cached provider catalogues are excluded; archives are unencrypted. Unsupported selected categories fail rather than silently vanish. Legacy archive review is separate and confirms whole-library replacement. Busy/cancel, picker unavailable/cancelled, corrupt/unsupported archives, recovery-required and unresolved-media results are all significant states. No destructive restore was run during this audit.

### About

Foundation replaces the generic preference surface with About app information plus four children: Release Notes, Open-source Licences, Credits & Acknowledgements, Technical Information. App information is the parent, not a fifth identical child. Catalogue/details weights are 44/56 within remaining workspace. Release data comes from bundled JSON; the current release is expanded, older rows toggle independently. Licence catalogue/text is local and asynchronous with generation guards and a four-entry text cache; the reader paginates long notices. Unavailable assets show a failure message rather than fabricated legal text. Credits retain mandatory text and approved assets; official HTTPS URLs may produce QR codes. Technical categories are Application & Build, Device & Android TV, Playback & Media Capabilities, Library & Storage, Diagnostics. Cached library count is explicitly not authoritative; codec reports are not a playback guarantee. These are read-only disclosures, not duplicate settings. Build-specific legal/signature conformance remains release evidence, not a new audit claim.

## Integration and preservation constraints

Preserve original preference names/types/value domains, proxy inversion, per-country provider keys, independent tracking/resume/inclusion state, source scheduling ownership, per-source rescan intent, credential/trust boundaries, Trakt account operations, IntroDB safe intervals, local diagnostic export and logical/legacy backup distinctions. Duplicated presentation is not automatically duplicated functionality. Hidden classic values can still be read by legacy consumers and portable backup rules. Neither toggling an integration nor switching the UI should erase credentials or media. No removal is recommended without documenting the consumer and migration implications.

## Limits and release safety

This is a source/documentation audit with tooling tests, not a complete device certification. Android/Robolectric tests were inspected but not rerun: sibling MediaLib/FileCore/native modules and prepared Android build are absent, and no APK rebuild was authorised. Exact per-device visible counts depend on capability/account state. Runtime-generated languages, provider catalogues and legal/component rows are unbounded templates rather than a fabricated fixed count. Source findings with weaker impact proof are intentionally classified as potential. Shield QA is wholly PENDING. Publication is limited to this new documentation branch; PR #20 stays draft and untouched.
