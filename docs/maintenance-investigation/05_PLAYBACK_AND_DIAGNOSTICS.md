## Actual playback paths

**VERIFIED, high confidence:** PlayerService owns session selection, startup position and durable checkpoints; Player opens an IMediaPlayer using MediaFactory. ## Defaults, retention and export

**VERIFIED:** defaultEnabled returns true and install reads saved preference with that default. `qa=true` is unconditional, so the recorder uses its highest bounded detail in all builds that call install; the `DEVELOPMENT_DIAGNOSTICS` build flag is not the current detail switch. Level selector is absent from the reorganized Settings UI, though LEVEL and configuration-monitor strings remain. The comment describing opt-in logging and ZIP README saying “off by default” disagree with executable behavior; this is a documentation defect in the export, not a reason to change the owner's default silently.

Private storage is `files/supernova-diagnostics`. Routine stream limit 256KiB, four rotations; playback one rotation; flight ring 252KiB / 60s plus frozen pre/post window. Important and manual/automatic incident streams are separated by UTC day with three rotations each; seven-day pruning occurs during important writes. This is not a strict global storage ceiling: current files, oversize single append/flight join, daily streams and pruning trigger affect total retained size. Routine aged data can persist until rotated or explicitly deleted. Propose a global byte/age cap and record incomplete windows when capped.

Export uses ACTION_CREATE_DOCUMENT on a separate Activity/worker and only DiagnosticArchive filename matches. ZIP includes build/device metadata, codec capability list, local JSONL, manifest, summary and coverage. It does not read preferences, credentials DB, raw logcat, media files or native private trace streams. Destination may be a cloud-backed Android document provider selected by the owner; this is user-directed export, not automatic telemetry. Existing logs can be exported after recording is disabled unless deleted. ## Privacy gap assessment

**VERIFIED source:** errors omit exception messages; Player errors use numeric codes; focus labels prioritize credential ancestry tags; sourceType drops locations to coarse schemes. Generic `event(String,Object...)` still accepts arbitrary Strings/Objects. Key filtering is a denylist, not a per-event field/type allowlist. `username` is not a banned key, and `safe` does not recognize bare usernames. Prefix matches do not prove a value is developer-owned; `uiLabel` accepts any ASCII words matching its shape.

The [synthetic sanitizer probe](evidence/diagnostic-sanitizer-probe.json) executes a Python translation of the exact regex rules against ASCII canaries. It retains a token after `Authorization: Bearer ...`, the second word of a password containing spaces, bare usernames and cookie fragments; it removes the full credential URL. **Java/Android execution remains UNKNOWN** because javac is absent. This is evidence of the generic boundary's insufficiency, not evidence of leaked real logs. Current producer call sites often already supply safe constants/numbers; preserve them.

`sourceType` does not enumerate `smbj`, `sshj` or `sftp`, so those actual browser protocols become “other.” This is a verified classification gap, not missing transport support. Recorder text/disable text/default comments should be made consistent only in an approved later release.

Separate logging exists: CustomApplication configures Logback asynchronously with optional external override. `logback_full.xml` defines a rolling-file appender (7 days, 50MB) but the default root attaches logcat only; `logback_user.xml` default is empty. **UNKNOWN:** real runtime override activation or file output. Existing FileCore/MediaLib logs interpolate URI/error messages; structured export excludes them, but structured sanitization cannot guarantee their logcat privacy. Sentry init is guarded by ENABLE_BUG_REPORT and auto-init providers removed; no Sentry upload was observed or performed here. All logging sinks need review before claiming absolute secret exclusion.

## PROPOSED minimal diagnostics release, provisionally 0.139

1. **Privacy first:** reuse recorder/storage/export; add immutable typed events with exact event-specific numeric/boolean/enum fields. Reject unknown field types/codes before queuing; arbitrary toString/error messages never enter production records. Review all sinks, and add Java production-boundary/export redaction tests when implementation is authorized.
2. **Reliable pairing:** attempt IDs for startup, playback open, seek and recovery; monotonic intent/boundary timestamps, target vs achieved position and explicit quality `callback/proxy/native/presentation/unknown`. Cancelled/superseded attempts stay distinct.
3. **Extend existing sampler:** elapsed sample interval, GC count/time deltas where supported, writer delays/important queue depth, export timing, trim-memory callbacks and bounded scan/query/read totals. Keep API-unavailable values unknown; no continuous heap dump or heavyweight trace.
4. **Controlled optional native bridge:** only after ABI review, add bounded numeric frame/audio/read counters. Upstream PCM/SurfaceFlinger tools are potential QA aids, not automatic production logging. Do not change native playback clocks to create measurement evidence.

Proposed event envelope: schema version, enum event, elapsed/UTC/process-local correlation, source enum, attempt ID, numeric target/achieved/time/bytes, outcome enum, backend/measurement-quality enum. Storage uses existing retention with explicit global cap and exporter snapshot outside long-held write locks. Proposed overhead budget: establish A/A noise first; accept only if logger CPU, allocation, disk and p95 action latency remain within owner-agreed limits (suggest starting thresholds 1% average process CPU and 2% p95 latency, **not measured facts**).

Default context decision: media titles/paths remain omitted for ordinary performance; a future purpose-specific optional file-failure field is permitted by owner planning only when safe fragments or opaque IDs cannot solve the problem. Never include usernames/credentials even within otherwise useful paths. Record purpose, enabled state, sanitization proof, short retention and export inclusion separately before approval. No raw log upload is authorized.
