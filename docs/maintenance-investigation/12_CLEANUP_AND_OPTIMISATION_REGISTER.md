## Required removal proof

For each proposed deletion record symbol/resource, exact baseline SHA, direct and indirect consumers, manifest/external intents, XML styles/qualifiers/IDs, reflective loading/serialized data, JNI export/registration, runtime feature flags, database migrations and backup readers. Check rarely used engines, phone/PiP/external playback, error paths and local/network subtitle selection. Build with release minification/shrinking and inspect actual removal; a debug test is insufficient. Maintain a rollback commit/data recovery boundary; databases need separate recovery because APK downgrade can delete data.

## Footprint and performance method

Current signed APK byte count is attributed to 0.138 receipt; tracked source bytes are separately inventoried. Future exact-source baseline/candidate builds must report compressed APK total/entries, per-ABI compressed/uncompressed native bytes, DEX count/size/retained classes, resources.arsc/assets/compiled resources, split/universal and installed data/cache footprint. Use same toolchain/flags/ABI/licence configuration and store hashes. Compare NOVA only with a documented like-for-like build, distinguishing product design/native differences. No compression/removal implies measured startup/memory/CPU improvement.

Optimization acceptance requires a meaningful outcome (e.g. smaller exact retained payload, fewer measured rebuilds, lower latency/memory trend) with no corpus/UI/data/privacy regression. Proposed thresholds require owner approval and A/A noise measurement before being pass/fail gates. No synthetic benchmark results are reported.
