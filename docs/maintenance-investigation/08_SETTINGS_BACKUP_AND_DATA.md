## Backup/restore end-to-end

**VERIFIED:** MediaLibraryBackupService exports Supernova format 1.0 with manifest, instructions, media DB/version, portable settings/named preferences, viewing history and selected artwork/source/provider association stores. Backup is unencrypted and can reveal library, viewing habits and sanitized paths. Credentials excluded is a design contract supported by BackupPrivacy and portable settings checks, not proof that every possible historic user string is harmless.

VerifiedBackup writes a temporary archive, fsyncs, reads every entry for CRC/size and only then promotes it. SafeBackup stages under a canonical UUID cache directory, enforces path containment/allowed entries/duplicates, caps total expansion at 4GiB, count at 100k and settings/named JSON at 4MiB; validates format/current DB version/quick_check/history/provider schemas/privacy before replacing live data. It awaits ViewingHistory writes and takes restore journal + ProviderDiscoveryGate + history/DB locks. Swaps retain old files, WAL/SHM and auth envelope; journal enables recover-before-startup. This substantial infrastructure already exists.

**INFERRED risks:** 4GiB staging plus retained/fresh/live copies can exhaust device storage; strict bounds do not guarantee enough free space. Process death mid-swap needs durable journal recovery fixtures, not only CRC success. Exclusive provider locks and long DB operations need deadlock/timeout/foreground-service verification. Existing journal captures original account preferences for recovery; keep it device-private and out of exports. TOFU identities and provider tokens are intentionally not portable credentials.

## Proposed regression and owner decisions

Use synthetic schemas with row/membership/watched/resume invariants, never private DBs in public PRs. Test v36/45/50/51/56/61/62 creation/upgrade paths, with especially artwork-owner uniqueness and direct-upgrade guards. Current minimum-supported restore is Supernova format1.0 at exact DB version; legacy NOVA archives are explicitly unsupported. Do not promise arbitrary cross-version restore.

Inject process death at journal prepared, each database/WAL swap, preference commit and final committed/cleanup stages; recovery must produce all-original or all-restored coherent state. Check disk full/locked cursor/active scan/queued history writes, malicious ZIP paths/duplicates, corrupted CRC/database, same-version manifests with wrong schemas, auth exclusion, viewing inclusion switches, no-data-loss on unavailable sources and backup over minified release. Owner must approve successor schema, archive compatibility and rollback data policy before any implementation.
