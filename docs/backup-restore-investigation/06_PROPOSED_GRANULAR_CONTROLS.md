# Proposed granular backup controls

**Proposal only; no controls or format changes implemented.** Current format 1.0 has two inclusion switches (history/resume), not the independence shown here. Recommended defaults below require owner approval. Already-set owner policy: **exclude all artwork from new exports, with no artwork switch**.

Define category-specific logical payloads before building UI. Do not expose switches that merely drop required shared DB files or wipe omitted live data. A single monolithic `media.db` cannot safely provide these separations. Incidental caches, housekeeping/work queues, scanner indexes and auth state are not user-facing backup categories.

## One switch per independently meaningful category

All rows: Off means **do not export that category**; on restoring a partial archive, the recommended policy is **leave destination category unchanged**, never interpret absence as “clear”. Explicit replace/clear is a separate reviewed restore action. On an empty installation, absent categories start with defaults/empty content. Structural manifest/checksums/category schemas are mandatory metadata, not selectable categories.

Collection definitions/memberships, saved lists, pinned/hidden media and preferred versions have distinct category ownership; their payloads must not duplicate one another. If stable membership cannot be supported independently for an unmatched file, show that dependency and unresolved count in export review; do not silently turn on paths or discard records. Source bookmarks and library sources require a new semantic split of legacy shortcut stores, not just separate ZIP-file checkboxes. Internal put.io discovery ownership must follow its related category as structural data, with no meaningless standalone ownership toggle.

No artwork, image cache, extracted thumbnails, episode stills, logos, backdrop/poster files, cached enrichment/technical/search/provider data, queued scans or cleanup commands in new logical exports. Keeping provider identity and explicit user image-choice metadata is a separate compatibility policy; it must not sneak image bytes back into new archives. Credentials, tokens, sessions, passwords, host trust, Keystore keys and Android permissions remain excluded; **no plaintext secrets control** is proposed.

| Supported player format/rotation/notification/play-mode and network-bookmark policy | Currently rejected despite storage; assess device portability and legacy reachability before adding respective settings keys |
| Legacy local-folder exclusion data | blacklisteds_db is omitted today despite active user exclusion controls; migrate relevant intent under Saved library sources, with explicit path warning and legacy compatibility fixture |
| Versioned settings intent/default provenance | Necessary to omit incidental defaults while retaining explicit default choices; design gate, not a value-equals-default filter |
| Durable metadata overrides / manual correction ledger | Preserve genuine user edits when downloadable metadata excluded; exact correction provenance currently implicit in DB relationships; high complexity, later phase |
| Personal external files such as NFO/subtitle contents | **Not recommended in this backup scope.** Not currently exported; separate file backup tool/category would materially change content/licensing/privacy/storage contract and needs a later explicit request |

## Export and restore review UX (proposed)

Display each independent label/description/switch, current selected categories and privacy warnings; show dependence transparently, not silently auto-selecting private categories. Summary includes expected/estimated size only if calculated, unmatched/pending counts, credentials/artwork excluded, and local/cloud destination integrity limitations. No “all changed settings saved” claim until every registered setter/default migration has passed synthetic acceptance.

Restore preview should show actual category payloads, omissions, schema/version and explicit replacement consequences. It should distinguish excluded versus intentionally empty, offer only validated independently safe category selections, and warn about unresolved matches, missing sources and device setting adjustments. App should use canonical Supernova components for app-owned controls; Android picker remains a system surface. Not an approved app-wide Settings redesign.
