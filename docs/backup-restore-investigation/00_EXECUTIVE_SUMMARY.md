# Findings and direct answers

**Format 1.0 is an unencrypted database snapshot plus allowlisted stored preferences, identity history, optional source/provider DBs and selected poster/backdrop files. It does not preserve every user-modified setting. It does not currently support independently restoring categories.**

Source-verified findings at signed 0.138:

1. Export emits seven fixed entries: `manifest.json`, `RESTORE_INSTRUCTIONS.txt`, `settings.json`, `named_preferences.json`, `supernova-viewing-history.db`, `db_version.txt`, `media.db`. It conditionally adds `shortcuts_db`, `shortcuts2_db`, `putio-associations.db` and file entries under `scraper_posters/` and `scraper_backdrops/`. The reader additionally accepts `scraper_pictures/`, which this writer never emits. Credentials/WAL/SHM/media/subtitle files are not exported. [Full inventory](01_CURRENT_ARCHIVE_INVENTORY.md), [MediaLibraryBackupService.java:253](https://github.com/heretoecode/Supernova/blob/b3504c2c4b1725f3070416d14b63e53ae1db3d74/src/main/java/com/archos/mediacenter/video/utils/MediaLibraryBackupService.java#L253).
2. Portable settings iterate `getAll()`, using a static allowlist and prefixes. **Stored unchanged defaults are included. Stored changed-back-to-default values are included. Removed/never-stored keys are absent and resolve to the receiving version's defaults. There is no explicit user-intent/default-version record.** Default preferences are cleared on restore. [Settings matrix](02_SETTINGS_AND_DEFAULTS_MATRIX.md), [SettingsBackup.java:13](https://github.com/heretoecode/Supernova/blob/b3504c2c4b1725f3070416d14b63e53ae1db3d74/src/main/java/com/archos/mediacenter/video/utils/SettingsBackup.java#L13).
3. Verified omissions include subtitle style settings, subtitle preparation switches, network scan interval, NFO read/write policy and Diagnostic Logging. This disproves preservation of every modified setting. Per-file subtitle delay/ratio and other player parameters remain in `media.db`; global subtitle presentation is a different store. [PlayerActivity.java:1893](https://github.com/heretoecode/Supernova/blob/b3504c2c4b1725f3070416d14b63e53ae1db3d74/src/main/java/com/archos/mediacenter/video/player/PlayerActivity.java#L1893), [BackupPrivacy.java:231](https://github.com/heretoecode/Supernova/blob/b3504c2c4b1725f3070416d14b63e53ae1db3d74/src/main/java/com/archos/mediacenter/video/utils/BackupPrivacy.java#L231).
4. Media matching is presently entangled with physical paths, scanner rows, scraper foreign keys and metadata in `media.db`. Manual corrections are the selected scraper relationships, not a separately portable correction ledger. History uses TMDB movie/show-season-episode identities, or a hash of exact sanitized location. Rename/offline/cross-device reassociation is not a universal capability. [Identity map](03_MEDIA_IDENTITY_PATHS_AND_HISTORY.md).
5. Both history inclusion switches default **On** in code. History Off / Resume On retains identity/duration/positive resume rows; Resume Off does not eliminate watched history or all per-file playback customisations. Media identities remain in the library even when both switches are off. [Four-state matrix](03_MEDIA_IDENTITY_PATHS_AND_HISTORY.md#history-and-resume-selection).
6. Export tries to exclude recognised downloaded art, then includes every remaining file in poster/backdrop directories. Remaining files are **not proven to be personal artwork**: orphan/cache files and missing URL references can also pass. The reported ~40 images/~5.5 MB cannot be classified without private inspection. New exports must follow the already-decided no-artwork policy; retain compatibility with old artwork-bearing archives. [MigrationBackup.java:25](https://github.com/heretoecode/Supernova/blob/b3504c2c4b1725f3070416d14b63e53ae1db3d74/src/main/java/com/archos/mediacenter/video/utils/MigrationBackup.java#L25), [MediaLibraryBackupService.java:505](https://github.com/heretoecode/Supernova/blob/b3504c2c4b1725f3070416d14b63e53ae1db3d74/src/main/java/com/archos/mediacenter/video/utils/MediaLibraryBackupService.java#L505).
7. `CreateDocument` creates the selected `.zip.in-progress` document **before** generation. Local ZIP generation is verified before copy, but the destination can be empty/partial during generation/copy. Destination bytes are SHA-256 read back before attempted rename and success toast. Provider rename can fail; success text then explains manual renaming. Preparation before opening the picker reduces placeholder time; standard SAF cannot guarantee universally invisible or atomic publication. [SAF report](04_SAF_EXPORT_IMPORT_AND_PERFORMANCE.md).
8. Source emits an ongoing notification and a success **toast**, then cancels notification ID 7. It does not post a persistent export-success notification or restart on export. The owner reported apparent exit at **12:41 Dublin** and a **12:33 notification**. Preserve both; the sequence, APK/date/clock/provider and cause remain unverified. [Incident report](05_INCIDENT_TIMELINE_AND_EVIDENCE_PLAN.md).
9. Restore accepts Supernova 1.0 with an exact fixed manifest category set and current DB version **62**; media validation is version + `quick_check` + privacy, not a full schema fingerprint. Existing maintenance's different-upstream-v62 collision remains material. Unknown/older NOVA backups are unsupported. [Compatibility report](07_RESTORE_COMPATIBILITY_AND_SAFETY_PLAN.md).

Journal robustness on hardware is still a future acceptance gate.
