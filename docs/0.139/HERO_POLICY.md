# Hero policy and verification boundary

Ten distinct indexed title identities: aim for five movies/five TV shows. Rank eligible source turns Recently Added, Recently Added, in-library Trending, in-library Popular, Because You Watched, repeating deterministically. Preserve each source order; Recently Added sorts descending added timestamp, identity as tie breaker. Dedupe by TMDB kind/ID when known, otherwise existing indexed title key. Apply five-per-type quota, then other-type shortage fill; eligible Recently Added supplies missing titles. A small library remains small. Sequential episode suggestions stay in Continue Watching, outside this title pool.

Rebuild on indexed snapshot, discovery snapshot, source settings, or successful-output generation change. Keep the currently displayed identity when possible on snapshot refresh. Exclude watched/in-progress titles and shows with watched/resumed indexed episodes, existing Continue Watching and process-local successfully started titles. Failed launch/preparation and Play clicks do not remove titles. Output is the active playing backend's rendering-start event or a playing TextureView frame; service also requires its initial position applied. Private mode creates no history/exclusion record. Existing persisted viewing state remains the durable source across process restart; no new hidden persisted history is introduced.

Home attach/resume starts a30-second idle window; every remote down/up, including navigation tabs, resets it. After inactivity auto advances every8seconds through the same transition as manual. Hidden/scrolled Home, covered windows, detach and reduced motion stop automatic advance; input and lifecycle resume restart idle. Horizontal hero key ownership consumes held down/up events during rebind. Transition updates only the hero cell and must retain unrelated row adapters, scroll and focus.

Pure policy tests cover quotas, source mix, fallback, uniqueness, scarcity, exclusions, exact clock boundaries and lifecycle. Production output callback tests cover prepared/error/stale/released backend and once-only positive output. Android integration tests validate actual pool and carousel routes. No native decoder/Shield success or performance claim follows from these tests; device playback and visual acceptance remain open.
