# Backup dependency and category audit — implementation stage

Baseline application source b3504c2c4b1725f3070416d14b63e53ae1db3d74; MediaLib5758074049bc153ac4967b4ecd21886469270076 with the existing Supernova patches. This read-only audit does not claim legacy data has never been used or that reflective/external clients do not exist.

* Legacy `user_collection`/`user_collection_item`: app store is `collections/UserCollectionStore.java`; no statically referenced app client outside that class. MediaLib provider has explicit table handlers. Modern Home stores `preview_home_rows41`; custom pages store `supernova_custom_library_page`; franchise membership uses provider `movie_collection`, not these legacy user tables. New format must exclude collection tables and relationships through a positive logical schema. No live-table drop, destructive migration or global deletion. Dedicated1.0 reader must separately retain its historical data contract; a missing category never deletes an unrelated destination store.
* `list_table`/`video_list_table` are independent: TraktService and browser lists routes create/write them; VideosByListLoader, Player UpdateNextTask and existing ChannelManager consume them. Native VIDEOS_BY_LISTS route remains. A logical saved-playlists payload needs durable movie/episode IDs and unresolved memberships; this does not add a new Saved Lists feature or change parked Shield integration. Do not discard these as Collections.
* Put.io selection/account/ownership stores are excluded entirely from new archives, without a switch. Existing live data and integration remain. Saved sources/bookmarks may not reintroduce Put.io associations indirectly.
* Expanded exact-column search found pinned writers in `utils/DbUtils.java` (`markAsPinned`/`markAsNotPinned`) and reachable legacy movie/TV/anime grid menus. Pinned movie/show state therefore is a meaningful category and must be covered; the earlier limited setter-name search was incomplete. Franchise Collection call sites are separate and do not authorize exporting legacy user_collection tables. Hidden media has active Details actions and `Archos_hiddenByUser` writes, so it also requires independent logical coverage. No data was excluded from a connected exporter based on the preliminary search.
* System-detected `media:`, `offline:` and `problem:` health entries are not user annotations. Only deliberate incorrect-match/review intent belongs to a logical review category; identities must be remapped or held unresolved.

Registry stage: ten independently owned settings categories, explicit typed keys, strictly bounded known dynamic keys. Includes saved subtitle appearance/discovery/prefetch, NFO policy, scan interval, diagnostic on/off and streaming provider choices. Stored default-valued intent is included. This is not a complete source-coverage claim: logical Home/custom pages/Watch Next/history/positions/matches/sources/bookmarks/per-title/list membership and legacy compatibility are still pending. The registry is not connected to an exporter yet; no2.0 compatibility promise or safe-restore claim.

Restore settings validation completes before creating an uncommitted editor. Replacement removes only keys owned by the selected category, preserving credentials, other categories and unknown destination state. Present-empty clears that selected category; omitted/unselected must never call replacement. The external multi-store journal still owns commit/rollback. Network-bookmark policy is a Boolean preference, not a bookmark payload. No raw diagnostic recordings, media database, artwork, subtitle bytes, authentication, path stores or provider caches are accepted here.
