# 0.138 subtitle provider and policy audit

The pinned app uses the OpenSubtitles REST API, version 1, through OpenSubtitlesApiHelper. The existing manual downloader queries one result page by hash and/or verified TMDB/IMDb identity, language, season and episode, then obtains a download link only after selection. Download responses supply account allowance, remaining downloads and reset time. Those real values are preserved; discovery searches are not download-quota consumption. Anonymous in-memory default quotas are not treated as verified provider limits.

Public API reference linked by existing source: https://www.opensubtitles.com/docs/api/html/index.htm . Attempts to retrieve the public documentation/terms at https://opensubtitles.stoplight.io/docs/opensubtitles-api and https://www.opensubtitles.com/en/terms returned 404 and 403 respectively on 2026-10-12. No terms text or live provider quota was obtained; no external terms-compliance claim is made. The implementation provides an explicit disabled-by-default Prepare Subtitle Searches preference. The approved intent policy runs when enabled, subject to the existing integration switch and chosen language preferences. There are no provider searches from the importer, scanner or metadata extraction. No speculative downloads or account logins are added.

Discovery is paced at one request per 30 seconds (a conservative application budget, not an asserted provider quota). HTTP 429, Retry-After (seconds or HTTP date), reported rate-limit remaining/reset, exponential backoff and provider cooldown survive restart. Positive results expire after 24 hours; genuine empty successful responses after six hours. Failures remain unknown and do not become negative availability. Query identity and language separate caches; reimported provider IDs reuse them. Hash-qualified queries are distinct, preserving file-match semantics. Manual requests take precedence over queued work and reuse matching cached results; an in-flight network request is bounded by a 15-second timeout. Manual requests honour provider cooldown; existing download quota checks remain in effect.

Selected hero requests are low priority; Watch Next/Continue Watching high; details visits are scoped to the selected playable title/series target; playback highest. Playback enqueues only remaining available, uncompleted episodes of the current season. Changing season/content clears obsolete speculation. Continue Watching's next-season episode is prioritised alone until that season actually starts. Background caches are private app data. Private-mode intent does not schedule or persist title searches; explicit manual search preserves existing behaviour.

Native technical retrieval already inspects embedded tracks; successful extraction now persists verified languages, subtitle availability and FFmpeg hearing/visual-impaired disposition bits. Local sibling sidecars are recognised by exact media basename and known extensions; language suffixes are recorded only when explicit. Unknown language is not guessed. Subtitle/SDH/AD badges describe inspected local playable media only. Provider search results, including explicit hearing_impaired where present, do not become local playback capability badges. Generic subtitles are never labelled CC, SDH or AD without evidence.

Outstanding live/device verification: API-key validity and current provider terms/headers, network remote-sidecar enumeration, native embedded-language/CC/SDH/AD fidelity, manual authenticated download integration and physical Shield pacing. No raw user recordings, diagnostics, account credentials or private cache records are committed or uploaded.
