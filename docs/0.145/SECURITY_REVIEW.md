# Dependency/security review — mitigations implemented, library findings remain

OSV was queried for all **135 unique Maven coordinates** in the existing 138-artifact runtime SBOM. The exact query scope and nine returned advisory records are retained in DEPENDENCY_ADVISORIES.json. All nine findings now have an individual reachability assessment and disposition in [JETTY_SECURITY_DISPOSITION.md](JETTY_SECURITY_DISPOSITION.md). No finding is suppressed. This does not clear native, test or build dependencies or establish absence of other vulnerabilities.

Jetty HTTP/server **9.2.30** is used by MediaLib's actual jUPnP servlet server/client. The candidate mitigates incoming ambiguous framing and connection reuse, reproduced private error disclosure and outgoing discovered-endpoint validation at this application's UPnP boundary. Eleven actual-library TCP/servlet/client integration cases pass locally, and five old-server negative-control failures demonstrate behavior changes. These cases are also required by the final protected Android conformance suite. Package-version advisories remain scan-affected; boundary mitigations and absent configured prerequisites are not a complete parser/library security fix.

The individual review covers TLS, HTTP framing, DefaultServlet/error handling, outgoing URI parsing, clustered sessions, cookies, standalone HttpURI validation and multipart requests. It identifies which prerequisite chains are absent in the configured transport and the vulnerable classes that remain bundled. Host JVM tests do not substitute for API23 or real Android UPnP-device compatibility. Protocol-correct close-after-response trades connection reuse for a single unambiguous exchange; older/provider-specific device behavior still needs acceptance.

Upstream MediaLib commit `44bf51b1de` explicitly retains Jetty9.2.30 for the Android API23 floor. A supported API23-compatible Jetty/jUPnP migration or maintained security backport needs custom-method/async/IPv6/provider and Android coverage, runtime hashes, SBOM/legal review and APK validation. A one-class parser override risks duplicate classes/ABI and provenance problems. Raising the SDK floor, removing UPnP or weakening TLS is not used to bypass that work. Compatible library replacement/backports remain genuinely deferred.

Upstream `e4696b972` mostly documents/suppresses lint findings and exports the suggestion provider; importing it wholesale would broaden Supernova's IPC access. Its later correction `ffd0eb50c` is adapted by keeping the provider private. Existing cleartext allowance supports configured local HTTP/WebDAV/UPnP sources. No TLS verification or certificate trust is weakened.

Native buffer arithmetic port `96d5f4fb55` is included and passes sanitizer boundary tests. Native FFmpeg9, OpenSSL4.1 and libass migration are not verified drop-in replacements for the reviewed FFmpeg8 runtime. The upstream inventory retains observed revisions; coordinated ABI, subtitle settings, native regression, licenses/SBOM and four-architecture device review remain required before replacement. No prebuilt substitution is used.

No physical device, installed application, LAN provider or AV chain is available. No startup/playback/memory profiling numbers or complete security clearance are claimed. Final software/signed-delivery results are recorded in RELEASE_REPORT.md and VALIDATION.json, separately from residual library risk and pending physical acceptance.
