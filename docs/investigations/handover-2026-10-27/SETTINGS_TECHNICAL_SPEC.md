# Settings technical specification

27 October 2026. Documentation/specification candidate; application implementation NOT authorised. [Master blueprint](../../design/SETTINGS_FROM_SCRATCH_BLUEPRINT.md) controls visual approval. [Mapping](../../design/SETTINGS_AUDIT_MAPPING.md), [audit](../../audits/settings-2026-10-26/AUDIT.md), [row ledger](SETTINGS_DISPOSITION.md) and [source verification](SETTINGS_VERIFICATION.json) control functional traceability. Preserve all approved visuals; numeric targets require Shield calibration. This document resolves routine architecture; it does not promote provisional category placements to owner approval.

## Architecture and state ownership

Implement a new Settings view hierarchy with the approved grid and category subsection rail/right controls. Keep the actual preference model, default SharedPreferences keys/types, external stores and owner handlers. Do not skin/reparent the existing three-pane hierarchy into the new layout. Keep the current activity entry contract, category shortcuts and navigation return path compatible. Separate model/action adapters from rendering; enumerate controls by audit ID plus actual key, type, capability visibility, enabled reason, live value/options, accepted-write handler and return anchor. A hidden item is not a row with an empty label.

Inflate/build the model through existing common capability setup and organisation, then bind the new view to its owners; extract side-effect handlers only where necessary and test equivalence. Never invoke both old and new listeners for one acceptance. Store no copied preference values in the view model. Read live preferences on entry/recreation, subscribe while active and detach observers/cancel asynchronous work on exit. Runtime choices come from their existing owner. Persisted invalid values use existing fallback/migration, never an arbitrary screenshot value. Service effects may occur on next playback or reconnect; descriptions must be honest about that timing.

For a native preference change: call its change listener, respect rejection, persist the typed accepted value once and refresh dependent enabled/options state without moving focus. Positive subtitle S125 is a proxy for inverse S052, not an independent new saved policy. Fix F02 by invoking the common acceptance/dependency path before applying the inverse state. No forced track or subtitle-language policy change. Action IDs (including diagnostic labels and JustWatch) are not saved preference keys. Streaming search/Show all and restore-review choices remain transient. Export choices use their existing synchronous commit/error handling.

## Components and navigation

| Component | Contract |
|---|---|
| Grid | Exact eight names/order/descriptions from blueprint, weighted 4×2, no scrolling at normal 16:9, unchanged official background, no permanent sidebar. Initial Playback & Video; arrows preserve row/column without wrap; OK enters; Back uses existing exit route. |
| Category page | Identity/description and only its own subsection rail left; active content right, no third pane. Retain per-category subsection, row and scroll anchors. First entry selects first actual subsection, not a hidden one. |
| Row | Stable identity by audit ID/key; title/supporting explanation and control, separator; minimum focus target 48dp. Grow/wrap for text scaling; do not shrink text just to fit. Focus is distinct from On/Off/selected state. |
| Toggle | Boolean only. Focus does not write; OK accepts once. Rejected/error writes retain value with visible reason. Disabled row explains capability/account prerequisite. |
| Single choice | Approved compact radio modal with live option IDs/labels, selected saved value, Cancel and focus return. Refresh switching S018 is 0/1/2, Dolby Vision S019 auto/off/force capability-adjusted; neither becomes a Boolean. |
| Multi choice | Check independent values in place, preserve row identity/order/focus until reopen; explicit completion where flow requires it. Language download list is not radio. |
| Text/forms | Reuse compact keyboard, limits/validation, password masking and explicit acceptance; no write on highlight. Numeric compatibility inputs need prepared-native validation before enforcing new bounds. |
| Action/editor/disclosure | Preserve confirmation, asynchronous busy/cancel/error state and original ownership; use existing Home editor, backup engine and About content. No invented toggles. |

Left/Right move between meaningful controls and subsection rail without toggling. Up/Down stay in current list and scroll the focused row into view. Back closes keyboard/modal/operation review first, then returns content→prior page/grid as appropriate; external Android picker return restores original action. Back at category returns to its grid card. Preserve anchor by stable ID through locale/account/capability rebuild; if removed, choose nearest surviving row or subsection, never a hidden view. Do not translate IDs. Orientation/activity/process recreation must not replay sign-in/export/restore/force-sync actions. Reduced animation must not obscure focus.

Use blueprint's later compact Playback section targets where earlier generic dimensions differ (55–65dp expandable setting rows, compact rail); grid typography/geometry remain calibration targets. Accessibility text scale may require scrolling in category pages; no truncated essential choice labels. Exact English grid descriptions must fit at reference scale. Screen reader labels expose title/value/enabled reason; announce accepted changes/loading errors without reading secrets.

## Category adaptation and disposition

Keep proposed eight destinations in the mapping (11 Playback & Video, 10 Audio & Subtitles, 24 Library & Home, 8 Streaming & Providers, 5 Appearance, 20 Connections & Integrations, 58 System & Maintenance, 6 About, 23 non-exposed definitions). Counts include gated and nested definitions, not visible row totals.

Playback: `playback_speed` enables player speed controls, not a saved speed selection. Keep external player, pause controls, projector, existing handheld resume/brightness gates. Video & Display uses actual refresh/Dolby/3D choices and hardware gates. Resume & Progress owns S105 and S072, distinct from S104 recording history; keep saved offsets when history tracking is disabled. Avoid duplicated controls between Library and Playback.

Audio/Subtitles: preserve passthrough capability and migration, spatialization/downmix interaction, original track and runtime audio language; advanced decoder/interface/speed/delay remain compatibility subsections. Language lists are supplied by MediaLib/OpenSubtitles/TMDb owners; System/audio/subtitle fallbacks differ. Download language selection may repopulate locale when empty on reconstruction. Generic languages use neutral symbols, flags only for true regional locales; Cantonese normalisation remains. Subtitle search preparation defaults Off, season preparation On; respect OpenSubtitles/Private Mode and do not auto-download.

Library/Home: metadata actions retain confirmations, asynchronous scrape/NFO/export services and writable-source limits. Keep independent watch-history clear/track, resume and backup policies. Home rows opens existing editor with all built-in/custom controls and draft cancellation. Remember views remains separate from Home definitions. Display all files shares its backend with Network & Files but must not broaden indexing.

Hidden disposition: every `REVIEW / NON-EXPOSED` row remains absent while preserving backend state. Do not resurrect classic Home rows/sorts, app theme/interface switches, legacy time/trailer/rating flags or advanced quit. S089/S101/S126 scan controls and S070 credentials belong to Network & Files, not duplicate Settings forms. S052 is inverse model behind S125. S091 sponsorship is legacy: no new sponsor switch in Foundation About. S106/S107 are compatibility inclusion models for nested backup, not extra top-level controls. Hardware-only cutout/downmix/brightness options keep existing platform gates; absence on Shield does not delete other-platform behaviour.
