## Database and rollback contract

Schema **64** uses `media-v64.db`, preserving legacy `media.db` as an old-APK logical rollback snapshot. Older
released helpers can delete unsupported schemas; merely adding a new onDowngrade override would not protect
rollback. The current helper refuses future versions normally. Migration is worker-only, cross-process leased,
checked, copied/upgraded privately, synced and atomically renamed. Failure retains old logical rows. SQLite
checkpointing can alter old journal headers: this is not a byte-identical old-file promise. Older APKs do not see
subsequent 0.157 edits, and two stores require extra disk space. Backup ZIP naming stays the logical `media.db`.

Frozen 0.153/0.154 fixtures were built from their verified historical schema-63 helper sources, not copied from a
current-schema test. Receipts and gzip/database hashes are in src/test/resources/upgrade157. They exercise metadata,
collection, hidden/watched/resume and retained opaque settings/auth files. They are synthetic historical-schema
fixtures, not the owner's accounts or a signed package-manager/hardware-keystore migration test.
