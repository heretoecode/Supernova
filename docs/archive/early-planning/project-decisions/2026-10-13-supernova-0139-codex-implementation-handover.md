## 3. Backup & Restore — functional and safety contract
**Primary user story:** New Android TV installation imports backup, recreates portable user intent (every explicitly saved/changed setting, even explicitly default-valued choices; accent, subtitle styling, language, streaming preferences, playback, Home ordering/custom rows, custom Library pages), reconnects devices/accounts separately, scans/indexes available media, fetches provider metadata, reattaches logical title state where safely matched, retains unresolved references for later matching. Do not promise universal rematching or hardware/permission portability.

**Non-negotiable exclusions:** Never include **any media content bytes** (video/audio/subtitles/posters/backdrops/stills/thumbnails/trailers) and never expose a toggle for them. Never include **credentials or authentication material** (passwords, tokens, API keys, cookies, sessions, signed secret URLs etc.), never a toggle. Positive allowlisted export schemas, privacy validation before publication, tests, no hidden leakage via JSON/SQLite/free-text/URI. Acknowledge that arbitrary user-entered text may itself contain sensitive strings and design mitigation; do not assert 'sanitised = anonymous'.
**Other exclusions:** New backups exclude Put.io associations, account/folder/file mappings and ownership, pending integration design; exclude legacy NOVA Collections and no Collections toggle. **Audit** whether old `user_collection`/`user_collection_item` tables are reused by active Supernova features; report conflict before dropping dependent user data. `list_table`/`video_list_table` are separately investigated, not automatically a user-visible feature. No raw logs or operational caches.
**Privacy:** Optional 'Filenames and locations' category controlling filenames, folder paths, local storage/network host/share locations and physical media locators; **default Off by delegated privacy-first design judgement**. Off must exclude locations across *all* categories including bookmarks/sources/matches/labels and provider associations, not just media DB. File browser bookmarks default Off and require appropriate path disclosure warning/dependency; never silently force location switch On. Title IDs/history can still reveal viewing tastes.
**History:** Watch history default On; Off warning says watched status/personalisation may not restore. Preserve portable provider movie/episode identity, completion/watched state, in-progress offsets (positions separately switchable). Do not invent lifetime watch counts unless reliable source tracking is implemented and verified. Preserve unmatched history pending safe reconciliation; no secret query parameters.
**Category semantics:** Every independently meaningful actual category has an individual toggle; enumerate from source, remove overlapping controls, define explicit dependency/omitted-category behaviour. On restore, **selected categories replace corresponding configuration**, **unselected categories leave destination untouched**; distinguish missing vs present-empty. Never delete absent optional DBs/art or unrelated categories merely because missing from archive. Confirm with pre-restore preview and impact warnings; use staged/journaled atomic-enough recovery with truthful rollback limitations.
**Format:** Design new versioned *logical* export of durable preferences, row/page configurations, title IDs, matching corrections, viewing state, not a blind whole-media.db copy. Full DB snapshot includes regenerable metadata, paths and potentially identifying data. Preserve dedicated **legacy format 1.0 reader** and clearly handle old artwork-bearing archives (new exports never contain art); do not delete existing user archives. Schema/version fingerprint and migration tests; no arbitrary v62 collision acceptance. Archive contains accurate `RESTORE_INSTRUCTIONS.txt`, version-specific, with warnings, compatible with actual code and UI. Provide concise in-app information pages.
**SAF:** Create Backup uses Android ACTION_CREATE_DOCUMENT/save picker; Restore uses ACTION_OPEN_DOCUMENT/open picker. Prepare and validate privately before publishing, readback/verification, truthful provider-specific completion/failure, no promise of universal atomic rename. Handle `.zip.in-progress` placeholders, cancel, retry, cleanup and progress/notification lifecycle; avoid misleading success toast or premature notification. On restore, validate archive before user confirms category impact and any overwrite. Diagnose observed ~12:41 apparent app exit / ~12:33 notification / 0 KB interim / eventual 16.87MB ZIP only with actual evidence, not assumptions.
**Tests:** no media or secret entries, URI sanitisation and free text, category matrix/defaults/omissions, independent toggles and no path leakage, history/positions combinations, collections/Put.io exclusion, settings coverage, fresh device/new paths/unmatched, failed SAF/cancellation, old 1.0 fixtures with artwork, interrupted restore recovery, UI/ZIP instructions consistency.

## 2026-10-13 owner clarification — hero / Continue Watching hierarchy
**Continue Watching is king.** Hero should surface eligible not-yet-started titles, including the **next newly available episode** when the user has watched preceding episodes (e.g. episodes 1 and 2 watched, episode 3 newly added). Once the featured movie or episode **actually begins playback successfully**, it leaves hero eligibility and belongs to Continue Watching. Never promote already in-progress titles to hero, and **do not implement an unapproved hero 'More Info' -> 'Resume' switch**. Ensure episode-level eligibility and state changes are covered by tests. Do not mistake mere Play click or Preparing Playback screen for confirmed playback.
