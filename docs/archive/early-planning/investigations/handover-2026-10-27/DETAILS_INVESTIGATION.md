## Navigation/data trace to instrument

Remote discovery uses `PreviewRemoteDetailsActivity` and waits for metadata plus availability before `bindRemote()`; measure separately from the local Home route. Follow backdrop/title-art identity through `OfficialTitleArtwork`, `TopNavigation` and `PreviewMoviePage`, rather than changing Home rotation.

Use existing `details_enrichment`, `Diagnostics.uiRebuild`, `focusRestored`, `ArtworkRequest` and `PreviewMetadataCache` evidence. Add bounded monotonic timestamps (no credentials, full URLs, filenames or review bodies) for selection/navigation, first useful draw, cache-read/core-section completion, each accepted UI state, artwork request/ready/error, and last visible geometry change. Log title identity/type/season, generation, cache source, section failure class and rebuild count. Capture main-thread layout work and frame timings alongside network duration. Test null→cached→partial→fresh and out-of-order delivery using controllable fixtures.

## Written-review extension proposal — scope approval required

Use the existing TMDb integration as the first candidate, not a new provider/key or OMDb activation. Before implementation approval, confirm current endpoint availability/terms, attribution, language fallback and movie/TV coverage using official API documentation and bounded fixture contracts. No live provider verification was performed here. Do not infer episode/season review support from movie/series support.

Candidate design: a compact “Read reviews” action within Reception opens a read-only scrollable reader retaining Reception's ratings. It needs author, provider attribution, optional genuine rating/date, review body, provenance link and bounded pagination. The current fact panels block descendant focus; adding an actionable control therefore requires explicit focus routing and visual review. This is a substantive UX extension, not a silent extra button. Until approved, preserve six-region Details design and prepare data contracts/tests only. No accounts, submission or invented reviews.

Model states independently: not requested, loading, content (possibly stale with refresh failure), successful empty, unavailable/offline and retry. Empty is only asserted after successful response with no usable reviews; error cannot become “No reviews.” Render provider content as inert text, bound size/count, reject malformed IDs/links and prevent review markup executing. Pagination must never delay core metadata or backdrop. Test huge/Unicode/empty/missing-author content, malformed data, timeout, cache fallback, cancellation and rapid title changes.
